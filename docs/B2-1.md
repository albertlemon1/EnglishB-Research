## Fase 1 · Propuesta de infraestructura (para aprobar antes de implementar)

### Principio

Una sola app para los cuatro subniveles. **Nada cambia en B1**: cada función nueva se activa por un campo del contenido (un tipo nuevo de ítem, un campo nuevo en la tarea) o por el subnivel declarado en `course.json`. Los módulos 1–6 se recorren con Playwright antes y después, como regresión.

### 1. Interfaz en inglés por subnivel

**Declaración.** En `content/course.json` se añade un campo a los subniveles de B2 (solo se añade, no se reescribe nada):

```json
{ "id": "b2-1", "code": "B2.1", "ui": "en", "...": "..." }
```

Sin el campo, la interfaz es la actual (español). B1.1 y B1.2 no lo llevan.

**Implementación.** Un archivo nuevo, `assets/js/strings.js`, con las ~80 cadenas del cascarón de lección en dos idiomas (`es`, `en`) y una función `t(clave)`. `lessonView` y `reviewView` fijan el idioma según el subnivel antes de pintar; `blocks.js` y `exercises.js` dejan de llevar texto literal y llaman a `t()`. Cubre: nombres y títulos de bloque, encabezados de sección, botones (*Check*, *Reset*, *Review my text*, *Show the annotated model*), etiquetas de corrección (*Correct* / *Look again*), tipos de ejercicio, flechas de entonación, *Lesson 121 of 270*, *Next: Practice*, mensajes de resultado, placeholders y avisos de audio pendiente.

**Qué queda en español en B2.1** (según el diseño, «quirúrgicamente»):
- **Bloque 3 completo**, cascarón incluido («Glosario fonético dual», «Cómo leer el AFH», «Grabar y comparar»), porque es el bloque de análisis contrastivo. El `meaning` de cada término pasa a ser una **definición en inglés** (es léxico, no fonética); el `afh` y las `alerts` siguen en español.
- **La autoevaluación** (encabezado y preguntas) y las **pistas de «Revisar mi texto»** (matriz L1), que son el mismo análisis contrastivo.
- **El cascarón general de la app** (inicio, ruta, método, barra superior): es navegación, no instrucción de lección, y el usuario la lee en español. *Alternativa:* si prefieres que también cambie dentro de un módulo B2, se hace con el mismo `t()`.

**Contenido autor.** En B2.1 se redactan en inglés: `summary`, `canDo`, `warmup`, `focus`, `intro` de cada bloque, `context` de escenario y diálogo, `use` y `note` de registros, preguntas de comprensión, `explain` de todos los ejercicios, `usage` de estructuras, matriz L1 (`title`, `text`), `scenario`, `brief`, `steps`, notas del modelo y `module.json` (`intro`, `canDo`, `blocks[].text`). Se mantiene `titleEs` (aparece en la ruta y en el módulo, que siguen en español).

### 2. Discovery con respuesta abierta (`"type": "open"`)

En B2, las tres preguntas de descubrimiento (semántica, sintáctica, pragmática) dejan de tener opciones. Esquema de la pregunta:

```json
{
  "kind": "syntactic",
  "type": "open",
  "q": "Look at the two highlighted forms. How is each one built, and which one goes with *since March*? Write the rule in your own words.",
  "minWords": 8,
  "signals": ["have|has been", "-ing|ing form", "past participle|third form|-ed"],
  "model": "*Have / has been + -ing* names an activity that started in the past and is still in progress, so it takes *since* or *for*. *Have / has + past participle* names a completed action, so it goes with a result (*three bugs*).",
  "criteria": [
    "You named both forms (have been + -ing / have + past participle).",
    "You said that the continuous form goes with *since / for*.",
    "You linked the simple form to a finished result."
  ]
}
```

Flujo en la app:
1. El alumno escribe su regla en un área de texto (se guarda al vuelo, como la tarea).
2. **Compare with the model**: se muestra la regla modelo y, debajo, los `criteria` con un selector *Yes / Partly / Not yet* para cada uno. Si hay `signals`, la app marca antes qué señales aparecen en su texto («Your answer mentions: *since / for* ✓ · *past participle* –»): es una pista automática, nunca un veredicto.
3. La pregunta cuenta como respondida cuando se han valorado todos los criterios; `ok` = todos en *Yes*. Se guarda el primer intento (como hoy) con el texto, para poder releerlo.
4. La **regla** se desbloquea al responder las tres preguntas, como en B1.

`check_content.py`: `open` exige `q`, `model` y de 2 a 4 `criteria`; `signals` son expresiones regulares válidas. En un subnivel con `"ui": "en"`, las preguntas de discovery deben ser `open` (el validador lo exige) y deben seguir siendo tres, una por `kind`.

### 3. Organizadores gráficos semicompletos (`"type": "organizer"`)

Un ítem nuevo, utilizable en `discovery.organizer` (entre el texto de análisis y las preguntas) y como ítem de `practice` o del repaso. Dos presentaciones con el mismo esquema de celdas: cada celda es un texto fijo o un hueco `{ "gap": "...", "accept": [...] }`.

```json
{
  "type": "organizer",
  "kind": "table",
  "prompt": "Complete the table. Type the missing form or meaning.",
  "columns": ["Example", "Form", "What it highlights"],
  "rows": [
    ["We{{'ve been working}} on it since March.", { "gap": "have been + -ing", "accept": ["have been + -ing", "have/has been + -ing", "have been working"] }, "the activity, still in progress"],
    ["We{{'ve fixed}} three bugs.", "have + past participle", { "gap": "the result", "accept": ["the result", "a result", "result", "completed result"] }]
  ],
  "explain": "Continuous = activity and duration (*since / for*); simple = result and quantity (*three bugs*)."
}
```

```json
{
  "type": "organizer",
  "kind": "timeline",
  "prompt": "Place the Third Conditional on the time line.",
  "points": [
    { "when": "Last quarter", "text": "We didn't secure the budget." },
    { "when": "Imagined past", "gap": "If we had secured the budget", "accept": ["if we had secured the budget", "if we'd secured the budget"] },
    { "when": "Imagined result", "gap": "we would have expanded", "accept": ["we would have expanded", "we would've expanded", "we'd have expanded"] },
    { "when": "Now", "text": "No expansion. Regret." }
  ],
  "explain": "Both halves are unreal and past: *had + participle* in the if-clause, *would have + participle* in the result."
}
```

Se corrige con un solo botón **Check**: cada hueco se compara con `norm()` (la misma normalización que `gap` y `fix`); los huecos fallidos muestran la respuesta; el ítem es correcto si todos los huecos lo son. En el móvil, la tabla se apila por filas y la línea temporal se vuelve vertical; se comprobará que no desborda.

`check_content.py`: cada hueco tiene `accept` no vacío; en `table`, todas las filas tienen tantas celdas como `columns`; en `timeline`, al menos un hueco.

### 4. Glosario sin traducción

En B2, los `chunks` llevan definición en inglés en lugar de traducción:

```json
{ "en": "fall behind (schedule)", "def": "to be slower than planned, so that work is late", "register": "casual", "example": "We're falling behind on the testing.", "syn": "lag behind", "ant": "be on track" }
```

- La tarjeta del banco de chunks muestra `def` y, si existen, `syn` / `ant` y el ejemplo.
- El popover que se abre al tocar un chunk resaltado muestra `def` (hoy muestra `es`).
- `check_content.py`: con `"ui": "en"`, cada chunk exige `def` y **rechaza** `es`, para que el retiro del español sea real y verificable. En B1 nada cambia.

### 5. Tareas sin frases-plantilla

Hoy la app **falla** si una tarea no trae `frames` (`t.frames.map`), así que el cambio es necesario. En B2:

```json
"task": {
  "format": "email",
  "steps": ["Thank them for the proposal and name it precisely.", "Explain the constraint and when it arose.", "Link past and present with a mixed conditional.", "Offer a concrete alternative.", "Close with a next step."],
  "keywords": ["unforeseen", "not feasible", "had secured", "would be", "as an alternative", "going forward"],
  "chunks": [...], "checks": [...], "model": {...}
}
```

- `frames` pasa a ser opcional; `steps` hace de esquema de contenido y `keywords[]` son chips de palabras clave (tocarlas las inserta, pero no dan sintaxis).
- `extra.frames` también opcional (`extra.keywords` en su lugar).
- `check_content.py`: con `"ui": "en"`, una tarea con `frames` es un error; `keywords` obligatorio.

### 6. Autoevaluación metacognitiva

`selfCheck` admite objetos además de cadenas (B1 sigue con cadenas y casillas):

```json
"selfCheck": [
  { "area": "impact", "text": "¿El tono de tu negativa atenuó la confrontación con el cliente? ¿Qué estructura lo consiguió: la pasiva, el condicional mixto o un atenuador (*unfortunately*, *at this stage*)?", "reflect": true },
  { "area": "register", "text": "¿Usaste *consequently* o *therefore* en lugar del coloquial *so*?" },
  { "area": "l1", "text": "¿Tradujiste «actualmente» como *actually*? Debe ser *currently* o *at present*." },
  { "area": "strategy", "text": "Si te faltó un término técnico (*feasibility*), ¿lo rodeaste con una paráfrasis en vez de dejar la frase a medias?", "reflect": true }
]
```

- Cada ítem se valora con *Sí / A medias / Aún no* (selector segmentado, como el quiz de registro) en vez de una casilla.
- Con `reflect: true` aparece una línea de texto («¿Cómo? Escribe la frase que lo consigue») que se guarda con la tarea.
- `area` colorea la etiqueta: *impact* (efecto social), *register*, *accuracy*, *l1*, *strategy*. En español, porque es la matriz de salida.
